# zero-desktop 录屏（recording）设计

截图模块的姊妹功能：全局热键唤起 → 框选区域 → 定时抓帧喂给 ffmpeg → H.264 mp4 落盘。
第一期只做**画面**，不录声音。

代码：`crates/zero-desktop/src/modules/recording/`，前端
`crates/zero-desktop/ui/src/modules/recording/`。

## 1. 职责切分

与 screenshot 同构：Rust 做平台脏活（抓屏 / 全局热键 / 子进程 / 输出），React 做框选与
控制条。**框选复用截图那套叠加窗**（`overlay.html`），靠 URL 的 `mode=record` 分流前端
行为——选完不进标注，直接开录。避免两份框选实现各自漂移。

| 文件 | 职责 |
|---|---|
| `mod.rs` | `RecordingSettings` + `Rect` + 读设置 |
| `ffmpeg.rs` | ffmpeg 定位（设置路径 → PATH → 常见位置，命中后 `-version` 实测）+ 编码参数 |
| `capture.rs`（windows） | 可复用 `Grabber`：整场录制只建一次 DC/位图，每帧只 `BitBlt` + `GetDIBits`；可选画鼠标指针 |
| `session.rs` | 会话状态机 + 抓帧线程 + ffmpeg 子进程管理 |
| `bar.rs` | 录制中的悬浮控制条窗口（`recorder.html`） |
| `commands.rs` | Tauri 命令 + 热键入口 |
| `output.rs` | 目录约定、文件命名、sidecar 元数据 |

## 2. 编码：为什么是外部 ffmpeg

三条路：管道喂 ffmpeg / Windows Media Foundation 硬编 / 纯 Rust 存 GIF-MJPEG。选了**第一条**：
本仓不引入任何编码器依赖，音频、硬件编码、格式扩展将来都只是改参数；代价是用户机器上
要有 `ffmpeg.exe`。

代价被这样兜住：路径是设置项（留空则自动查找），**框选之前就先探一次**——不能让用户框
选半天才被告知没装 ffmpeg；找不到时录屏页顶部常驻一条黄色提示 + 下载链接，而不是静默失败。

线格式：`-f rawvideo -pix_fmt bgra -s WxH -r FPS -i -`。GDI 抓出来就是 BGRA，**不做
BGRA→RGBA 翻转**，省掉每帧一遍全画面字节交换。出片 `-pix_fmt yuv420p`（播放器通吃），
它要求宽高为偶数，所以录制矩形一律向下取偶。`-movflags +faststart` 让拖动定位不卡。

## 3. 时间轴：补帧而不是丢帧

喂给 ffmpeg 的是**定帧率**裸流，第 N 帧就代表第 N/fps 秒。抓屏偶尔卡一下（切窗、GPU 忙），
如果只是「少写几帧」，整段视频会越录越快、和实际时长对不上。

所以抓帧线程每轮按墙钟算出「此刻本应写到第几帧」，落后就用刚抓到的这帧补齐（单轮上限
`MAX_CATCHUP = 4`，卡顿几秒后不该一口气灌上百帧把 ffmpeg 顶死）。静止画面的重复帧对 x264
几乎不花码率，换来时间轴始终正确。

暂停不写帧、也不计时：`elapsed = 墙钟 - 累计暂停`，所以暂停在成片里表现为直接跳过。

## 4. 状态机与线程

`idle → recording ⇄ paused → idle`，进程内**同时只允许一场录制**。不是实现偷懒——热键是
「按一下开、按一下关」，控制条也只有一条，允许并发会让「现在按停止是停哪一场」变成用户
答不上来的问题。

一条抓帧线程独占 GDI 资源与 ffmpeg 的 stdin，主线程只通过两个 `AtomicBool`（stop / paused）
跟它通信，抓帧线程绝不回调主线程——避免热键回调 ↔ 抓帧线程之间出现锁序问题。

几个必须做对的收尾：

- 停止时**先关 stdin 再 `wait()`**：关 stdin 是在告诉 ffmpeg「没有更多帧了」，它据此写完
  moov 正常退出。少这一步文件缺尾，播放器打不开。
- 抓帧线程无论从哪条路径退出都要置 `finished`（`FinishGuard`），否则状态会永远停在
  `recording`，控制条也永远关不掉。
- ffmpeg 中途自己挂掉（磁盘满等）→ 线程自行结束，状态对外即 `idle`，控制条自动关闭，
  真实原因从 stderr 捞出来（stderr 全程有线程在读，不读会写满把 ffmpeg 自己阻塞住）。
- 关主窗退出前若在录制，先正常停止再退——否则留下一个没写完的 mp4 + 一个孤儿 ffmpeg。

## 5. 悬浮控制条

录屏一旦开始，画面上没有任何东西表明「正在录」，既容易忘关，也没法不切窗口就暂停/停止。
控制条给三件事：**计时、暂停、停止**（外加「丢弃」= 停止并删文件）。

- 计时以 **Rust 侧 `elapsed_ms` 为准**，不在前端自己 `setInterval` 累加——暂停、卡顿、
  系统休眠都会让前端计数和真实时长分家，而这条计时正是用户判断「录够了没」的唯一依据。
- 摆放优先在录制区域**外面**（下方 → 上方）；整屏录制时无处可躲，压在右下角并被录进画面，
  这是无法回避的取舍，不假装解决。整条可拖动，用户能自己挪开。

## 6. 输出

- 视频：`<workspace>/recordings/<yyyyMMdd-HHmmss>.mp4`（同秒重录加毫秒后缀，绝不覆盖）。
- sidecar：同名 `.json`，存 `duration_ms` / 宽高 / fps / 帧数。mp4 的时长要解析容器才能拿到，
  而停止那一刻我们本来就知道，写一行 json 比让前端去 ffprobe 便宜得多。
- 列表 / 删除 / 另存为 / 定位都做了「路径须在录屏目录内」的规范化校验，防路径穿越。

## 7. 全局热键

截图与录屏共用 `tauri-plugin-global-shortcut` 的**同一张全局表**，而唯一可靠的清场手段是
`unregister_all()`。所以注册收拢到 `modules/hotkeys.rs`：任何一方改热键，都从那里整体重注册
两个，否则谁保存设置谁就把对方的热键抹掉。

保存设置的顺序是「纯解析校验 → 写盘 → 整体重注册」（重注册是从磁盘读热键的），注册失败
（多为被别的软件占用）回滚设置并按旧值重注册——不能出现「界面显示新热键、实际按了没反应」。

默认 `Ctrl+Alt+R`，与截图的 `Ctrl+Alt+A` 并列。

## 8. 已知取舍 / 后续

- **不录声音**。系统声音要走 WASAPI loopback + 混麦 + 音视频同步，是另一个量级的活儿，
  单独一期。
- **抓帧走 GDI `BitBlt`**，够用且与截图共用心智模型。高帧率 / 大分辨率下掉帧明显时可换
  Desktop Duplication API（DXGI），那是纯优化，不影响本文档的任何接口。
- **仅 Windows**。命令在所有平台注册，非 Windows 调用即返回「仅支持 Windows」。
- ffmpeg 依赖用户自备。将来若要免安装，可打进安装包或首次使用时下载——那只是换一种
  「怎么拿到这个 exe」，录屏本身的代码不用改。
